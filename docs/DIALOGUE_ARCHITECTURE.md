# Диалоговый сбор данных для floorball.kz

## Пользовательские режимы

В интерфейсе используются только естественные формулировки:

- «Продолжить как тренер» — данные города, клубов, расписаний, игроков и медиа;
- «Продолжить со стратегией» — миссия, видение, ценности, цели и направления;
- «Продолжить историю» — история, достижения и дорожная карта;
- «Продолжить о руководстве» — публичные профили руководства и согласия.

Технические слова `pattern`, `spec`, имя таблицы, JSON path и hash пользователю не показываются.
Доступные варианты фильтруются по роли. Выбранный режим, версия определения и его SHA-256
закрепляются за сессией, поэтому изменение файла не меняет незавершённый разговор молча.

## Источники истины

1. Версионированные определения диалога в `src/floorball_bot/dialogue/specs` задают поля,
   вопросы RU/KZ, обязательность, зависимости, приватность и направления DB/site.
2. PostgreSQL хранит подтверждённые факты, черновики, происхождение, согласия и прогресс.
3. JSON-контракт сайта является детерминированной проекцией одобренной ревизии БД.
4. Codex не является источником истины и не принимает решения о правах, полноте,
   согласиях, одобрении или публикации.

Google Forms остаются внешним каналом ввода и материалом для сверки определений, но не
заменяют типизированный контракт. Изменение формы сначала выявляется тестом дрейфа, затем
оформляется новой версией определения и миграцией данных.

## Каждый вызов Codex

Приложение, а не модель, выполняет последовательность:

1. Проверяет активного пользователя, роль и допустимую область города.
2. Загружает закреплённую версию определения и проверяет SHA-256.
3. Строит через фиксированный проектор типизированный, минимальный и очищенный снимок БД.
4. Обычным кодом вычисляет отсутствующие поля и разделяет их на уровни обязательности.
5. Передаёт Codex полный текст общей политики, выбранное определение, отчёт о пропусках,
   безопасный снимок и пользовательское сообщение как недоверенные данные.
6. Проверяет структурированный патч: разрешённые поля, типы, размеры, роль, область и базовый
   hash снимка. Неизвестные поля и устаревшие патчи отклоняются.
7. Сохраняет новую ревизию/событие с происхождением. Канонические публичные таблицы не
   изменяются до подтверждения пользователя и редакторского одобрения.

Codex запускается в изолированном временном каталоге без DB credentials и не обязан иметь
доступ к файлам репозитория: всё необходимое приложение передаёт явно при каждом основном и
повторном repair-вызове.

## Обязательность данных

- `required_to_start` — без значения нельзя правильно определить субъект разговора;
- `required_for_submit` — блокирует отправку черновика редактору;
- `required_for_publish` — разговор можно закончить, но публикация заблокирована;
- `recommended` — важное дополнение, которое можно внести позже;
- `optional` — не влияет на готовность.

Детерминированный evaluator выбирает первый пропуск по приоритету. Модель может естественно
переформулировать не более двух следующих вопросов, но не может понизить обязательность.
Несколько фактов в одном сообщении принимаются одним патчем. `/status` и `/resume` используют
тот же сохранённый снимок прогресса; `/submit` проверяет критические поля повторно.

## Безопасный контекст БД

Контекстный шлюз предоставляет только фиксированные проекторы выбранного режима:

- для тренера: публичные названия города, заполненность описаний и метрик, клубы, расписания,
  одобренные профили игроков и покрытие медиа/согласий;
- для федерации: заполненность разделов стратегии, истории и руководства, публичные роли,
  источники и состояния редакторской проверки.

Произвольные имена таблиц, SQL и shell не принимаются. Telegram ID, личные телефоны, токены,
закрытые доказательства согласий, исходные сообщения и пути файлов в снимок не входят.
Операторская CLI-команда выдаёт тот же JSON, который получает агент, чтобы диагностика и
поведение в продакшене не расходились.

## Путь в сайт

Публикация допускается только для неизменившейся одобренной ревизии:

`PostgreSQL → типизированный projector → PublicCity/federation schema → точные JSON bytes →`
`изолированный worktree → frontend contract tests/build → preview diff + nonce → push`.

Импорт и экспорт обязаны сохранять вложенные клубы, расписания, игроков, галерею, агрегаты,
разделы федерации и руководство. Для каждого fixture действует round-trip/golden test. Любое
поле без явного DB target и site target считается ошибкой определения, а неизвестное поле
frontend-контракта — ошибкой сборки, не поводом молча его удалить.

## Согласия и приватность

Контакты закрыты по умолчанию. Публикация контакта, профиля или изображения требует отдельного
состояния согласия; для несовершеннолетнего дополнительно требуется подтверждение законного
представителя. Отзыв согласия блокирует следующую публикацию и создаёт задачу на снятие уже
опубликованного материала. Свободный текст никогда не считается автоматическим одобрением.

## Проверка опубликованных форм

25 августа 2026 года четыре маршрута были открыты в авторизованном Chrome без отправки данных.
Все маршруты перенаправляют на ожидаемые Google Forms. В форме руководства перед заголовком
«Тип формы для сайта» визуально присутствуют пять безымянных элементов «Вариант 1»; этого нет
в текущем Apps Script, поэтому это зафиксированный дрейф опубликованной формы, который нужно
исправить в Google Forms вручную или пересозданием формы после отдельного подтверждения.

## Минимальные приёмочные проверки

- все четыре определения валидны, имеют уникальные поля, RU/KZ-вопросы и DB/site mapping;
- каждый основной и repair-вызов Codex содержит spec hash и context hash;
- критические пропуски блокируют submit, а optional — нет;
- resume после перезапуска восстанавливает ровно ту же версию и прогресс;
- устаревший patch и поле вне allowlist отклоняются;
- restricted trainer не получает federation/city-admin/media/publish возможности;
- DB context не содержит приватных идентификаторов и контактов;
- полный city и federation fixture проходит DB → export → frontend contract без потери полей;
- preview не может быть опубликован другой ревизией или без повторного подтверждения.
